# Бэклог

Задачи по приоритетам. Внутри тира порядок не строгий. Детали активных задач — в `plan.md`.

## Руководящий принцип: интегрируемся, а не заменяем

Venty не пытается заменить 2gis (карта), Instagram, Telegram (чат) и другие сервисы.
Venty — это **лента и точка распространения** городских событий; глубокую функциональность
делегируем туда, где она уже удобна, через ссылки. Это снижает стоимость разработки и
трение, и укладывается в ugly-MVP. Следствия отмечены в пунктах ниже.

## В работе

### Профиль пользователя (device-local)

- План — в `.orch/plan_profile.md`.
- **Соц.сети в профиле** — пользователь добавляет ссылки (Telegram, Instagram и т.д.).
  Прямое воплощение принципа «интегрируемся, а не заменяем»: контакт и общение уходят
  в привычные сервисы, Venty их не дублирует. Полезно на раннем этапе.
- При появлении авторизации профиль переезжает на серверный аккаунт; «выйти» становится
  настоящим logout (сейчас — сброс локальных данных), «друзья» получают backend
  (сейчас — плейсхолдер).

## P0 — дёшево и прямо усиливает ядро (лента города + распространение)

- **Фильтр по городу + поиск в ленте.** Само обещание продукта — «все события города».
  Сейчас лента валит всё подряд; без фильтра «найти интересное» не работает.
- **OG/preview метатеги на веб-странице ивента.** Сам механизм роста: ссылка в мессенджер
  → читаемое превью (название/дата/место). Без них главный distribution-канал не работает.
  Проверить наличие, добавить.
- **Кнопка «поделиться»** с готовой ссылкой на странице ивента — замыкает growth-петлю.
- **Лайк.** Часть заявленного флоу «нашёл → лайкнул → вступил в чат», сейчас отсутствует.
  Device-local, как профиль.
- **Лента: прятать прошедшие, сортировать по ближайшим.** Сейчас сортировка по `created_at`,
  прошедшие висят. Нужен фильтр `starts_at >= now`.
- **«Мест осталось» из `capacity`** + состояние «мест нет». Поле уже есть, не используется.
- **Статусы отклика: убрать «не могу», свести к «иду».** «Не могу» мёртв для открытой ленты.
  MVP — бинарно: отклик = один тап, статистика = одно число. (Тоггл «может» — см. P2.)

## P1 — заявлено в MVP, дороже; через интеграцию дешевле

- **Чат на ивент — через внешнюю ссылку.** По принципу: организатор кладёт ссылку на
  внешний чат (Telegram-группа/канал), участники переходят. Дёшево и доступно сразу.
  Встроенный чат — только если внешнего окажется мало. Это же закрывает удаление поля
  `comment` из формы отклика: канал общения есть с первого дня, записка организатору —
  работа чата, второй messaging-surface не плодим.
- **Карта — встроенная, на технологии 2gis (MapGL).** Решено: подключаем интерактивную
  карту сразу, а не отдаём место ивента ссылкой во внешнюю карту. Берём стек 2gis —
  привычный для нашего региона (узнаваемые тайлы, POI, адресация). Место ивента =
  координаты + пин на карте внутри приложения; лента событий ложится на карту (часть
  заявленного MVP-функционала). Осознанное отступление от «интегрируемся, а не заменяем»:
  карта — одна из двух осей продукта (лента + карта), ради UX держим её внутри.
  При реализации сверить актуальный SDK/MapGL и его совместимость с Expo v56 через
  context7 (web — MapGL JS, нативно — 2GIS Native SDK).
- **Категории на активности + фильтр.** Сейчас у активности нет категории, а профиль
  (интересы) на неё ссылается. **Фундамент** для фильтра ленты, матча с интересами профиля
  и будущих рекомендаций. Без поля категории интересы профиля декоративны. Если планируем
  discovery — добавить раньше остального P1. Решено: одна обязательная категория из
  фиксированного словаря (не теги — см. P3). План — в `.orch/plan_categories.md`.
- **Базовая модерация.** Кнопка «пожаловаться» (дёшево) + rate-limit / IP-лимиты на создание
  (сервер). Прямо в MVP-scope доки.

## P2 — рост и удержание

- **Пуш-напоминания** о начале ивента (за N часов) — сильный retention-крючок.
- **Собственный встроенный чат ивента** — эволюция внешней ссылки на чат (см. P1).
  Свой messaging-surface (realtime, история, привязка к участникам) вместо ухода в
  Telegram. Делать, только когда внешнего чата окажется мало: дорого (realtime-бэкенд,
  модерация, роли), поэтому не раньше стабильной аудитории. Внешний `chat_url` тогда
  остаётся опциональной альтернативой, не выпиливается. План внешнего чата — `.orch/plan_chat.md`.
- **Вход и регистрация (опционально).** Настоящая авторизация (Supabase Auth, таблица
  пользователей, владение активностями). **Жёсткое требование:** анонимный путь сохраняется —
  пользователь может отправить ссылку незарегистрированному другу, и тот откликается просто
  по форме, как сейчас. Регистрация не должна становиться барьером отклика. Для авторизованных:
  имя/телеграм в отклик подтягиваются из профиля → форма почти в один тап.
- **Тоггл «только для авторизованных» при создании ивента** — fast-follow к авторизации
  (выше), не раньше: без аккаунтов «авторизованный пользователь» не существует, тоггл —
  no-op. Per-ивент opt-in выбор организатора (закрытая встреча, member-only комьюнити,
  отсев рандомов/спама), **не** платформенный отказ от анонимной формы. **Жёсткое правило:
  дефолт — ВЫКЛ**, иначе ломает снижение трения и виральное распространение (анонимный
  отклик по ссылке — ядро роста). Дёшево по паттерну `chat_url`: поле активности
  (`require_auth bool`) + одна ветка на `app/a/[slug].tsx` (форма vs «войдите / откройте
  приложение»). Триггер на реализацию — спрос на приватные/member-only ивенты или спам.
- **Тоггл «может» при создании ивента** — fast-follow, когда подтвердится спрос
  capacity-strict организаторов. Стоит не сам тоггл, а полная ветка `maybe` сквозь стек
  (схема, маппер, колонка БД, переменный UI, статистика, capacity-логика). Если строим:
  **дефолт — ВКЛ**, opt-out для строгих. Правило: capacity мерит только «иду», «может» =
  информационный «+N возможно».

## P3 — позже, вне раннего MVP

- **Trending / рекомендации в ленте** — док явно выносит за MVP, не трогать рано.
- **Свободные теги на активности (Instagram/TikTok-стиль).** Без лимита, произвольный
  текст от организатора — слой органического дискавери поверх категорий (P1). Работают
  только на масштабе: нужен объём контента и поиск по тегам, иначе декоративны (свободный
  текст не фильтруется и не матчится с профилем). Технически дёшево и независимо от
  категории: колонка `tags text[]`, поле в форме, поиск по overlap. Триггер на
  реализацию — появление поиска и заметного объёма контента.
- **Монетизация** — после 3000–5000 MAU: реклама, подписка организатора, featured placements.
- **Продвинутая модерация** — верификация (телефон), доверительные уровни, блок по разбору
  жалоб. Актуально только при стабильной аудитории.
